# 站点（对话建站与平台托管）

> 最后更新：2026-10-07

「站点」让用户在对话里描述需求，由智能体生成完整的静态网站并一键发布——平台直接托管，任何人凭链接即可访问，之后还能继续通过对话迭代更新。整条链路：沙箱内生成多文件站点 → `publish_site` 工具发布 → nginx 反代后端托管路由对外服务。

站点功能属**社区版（CE）**，入口在「实验室」（需管理员开通实验室权限）。

## 使用方式

1. 在对话里直接提出需求，例如「帮我做一个产品介绍网站并发布」。智能体会在沙箱里生成完整的静态站（HTML/CSS/JS/图片，须有 `index.html` 入口），然后调用 `publish_site` 工具发布，并把访问地址（形如 `/site/<slug>/`）交付到对话里。
2. 打开「实验室 → 站点」可管理自己的全部站点：打开、复制链接、修改标题 / 访问地址 / 可见性 / 访问密码、删除。
3. 要修改已发布的站点，在**任意对话**里描述改动即可，不必回到原来那段会话——智能体先用 `list_sites` 工具查出站点编号与源码目录，再带 `site_id` 重新发布，URL 不变、版本号 +1。同一账号有多个站点且描述不明确时，智能体会先问你改哪一个。

## 可见性

| 档位 | 行为 |
|---|---|
| 公开（默认） | 任何人凭链接访问，无需登录 |
| 团队 | 指定团队的成员登录后可见 |
| 私密 | 仅站点所有者本人登录后可见 |

## 访问密码

访问密码是可见性之外的一道独立闸门：可见性决定「哪些登录用户能看」，密码决定「拿到链接的人要不要先验证」。公开站点设了密码后，访客打开链接先看到**统一的密码验证页**——所有加密站点共用这一个页面，由后端直出，不依赖前端构建。

- 在「站点管理 → 设置 → 访问密码」里设置、修改或关闭；只有站点的创建者（团队项目站点则是项目管理员）能操作。
- 验证通过后浏览器拿到一枚仅对该站点生效的凭据 cookie，有效期 12 小时，过期需重新输入。
- 改密码或关闭密码会立刻让已发出的凭据全部失效。
- 能管理该站点的人登录后免密进入。
- 密码只以 Argon2id 哈希存储，明文既不落库也不通过接口回传；接口只回传「有没有设密码」。
- 密码尝试按 IP + 站点限流（每个后端进程 5 分钟 10 次；多 worker 部署下上限按 worker 数相应放大）。
- 公开表单数据接口遵守站点可见性与访问密码；只有显式允许匿名提交的 SQL 表可接收访客写入，访客不能查看记录。

## 版本与回滚

每次发布生成一个不可变版本目录，线上 URL 原地切换。「站点管理 → 版本」可查看历史版本并一键回滚；回滚后再次发布，版本号接历史最大值递增。

## 数据库与 MCP

静态网页不创建数据库。有表单或持久化需求时，代理使用 `manage_application` 创建结构化 SQL 表，再将前端提交连接到 `/site/<slug>/__api/data/<table>`。管理员在「站点管理 → 数据与 MCP」查看表结构、记录、导入及导出。全部本人应用在站点列表的应用面板管理；删除网页后数据库仍可在该面板查看。

用户要求 MCP 时，发布声明式查询工具、服务地址和独立访问凭据；MCP 可以不生成网页。数据库与 MCP 共用数据服务。产业知识中心导入需要企业版及插件授权。

旧 KV 与旧表单收集接口、工具、前端入口已删除。升级归档和恢复流程见[应用数据库与 MCP 托管](application-hosting.md)。`__api/` 仍为保留前缀。

## 访问统计

平台统计每个站点的 HTML 页访问次数（资源文件不计），在站点卡片与「分享记录」页展示；已发布站点同时出现在「分享记录」页顶部区块，便于统一管理对外链接。

## 托管与安全

- 站点文件按版本存储在平台存储后端（`sites/<site_id>/v<版本>/`），本地与云存储（S3/OSS）模式均支持；发布新版即时生效，历史版本保留（本地模式保留最近 3 版）。
- 访问路径 `/site/<slug>/…` 由 nginx 原样反代到后端公开托管路由，由后端控制可见性、缓存与安全响应头。
- 公开站点响应带 `Content-Security-Policy: sandbox`（不含 `allow-same-origin`）：站内脚本以独立源运行，无法携带访问者登录态调用平台接口；相应地站内 `localStorage` / cookie 不可用。
- 所有站点响应带 `X-Robots-Tag: noindex`，不进搜索引擎。

## 限制

- 站点本体为静态文件；动态能力由应用 SQL 数据接口与声明式 MCP 提供，不支持自定义服务端逻辑。
- 单站 ≤ 300 个文件、总量 ≤ 30MB、单文件 ≤ 10MB；单用户 ≤ 50 个站点。
- 内网部署时外部 CDN 资源可能不可达，样式脚本建议内联或本地化（智能体默认遵循此约定）。

| 环节 | 位置 |
|---|---|
| 发布与查询工具 | `src/backend/mcp_servers/site_publish_mcp/`（`publish_site` / `list_sites`，由「站点」插件提供） |
| 内部接口 | `src/backend/api/routes/v1/internal_sites.py`（`/v1/internal/sites/publish`、`/v1/internal/sites/list`） |
| 站点查询服务 | `src/backend/core/services/site_listing.py`（本机与云端统一记录格式） |
| 业务服务 | `src/backend/core/services/site_service.py` |
| 公开托管路由 | `src/backend/api/routes/sites_serve.py`（`GET /site/{slug}/{path}`） |
| 管理接口 | `src/backend/api/routes/v1/sites.py`（`/v1/sites`） |
| 访问密码 | `src/backend/core/services/site_password.py`（哈希 + 凭据）、`src/backend/api/routes/site_gate.py`（统一验证页） |
| 数据表 | `sites`（`core/db/models/site.py`） |
| 前端管理面板 | `src/frontend/src/components/sites/SitesPanel.tsx`（实验室 → 站点）、`SitePasswordField.tsx`（密码管理） |

环境开关：`SITES_ENABLED=false` 可整体关闭发布工具（默认开启）。

## 项目转换后的站点协作（EE）

个人项目转为团队项目后，站点继续关联同一个项目。站点 ID、访问地址和历史版本不会因为目录移动而重建；无需手动修改站点代码地址。应用数据库当前按应用所有者鉴权，不会自动继承团队协作权限。

团队只读成员可以查看项目源码和站点卡片；编辑成员可修改源码、发布原站点的新版本；所有者和管理员还可管理站点设置、版本回滚和删除。管理权限与访客可见性独立：转换和重新发布不会自动把私密站点改为团队或公开站点。

静态团队站点从已保存的项目源码发布。构建型站点先在团队项目会话中用 bash 构建，工具返回当前项目工作目录；发布时 `source_dir` 指向该目录，`src_dir` 指向独立构建产物目录（例如 `/workspace/.site-dist`）。源码与工作副本不一致，或发布期间其他成员更新源码时，系统拒绝发布并要求重新构建。构建产物不会替换源码项目。显式指定团队站点 ID 也必须使用对应项目会话。

## 并发与故障隔离

站点详情只校验管理权限，不获取站点排他行锁。发布新版本、修改设置、回滚和删除仍按写操作加锁。同步数据库和存储操作在工作线程执行，单个请求等待数据库锁时，健康检查仍可响应。访问次数更新失败时回滚该次事务，已读取的页面仍正常返回。

PostgreSQL 等锁上限沿用 `DB_POOL_TIMEOUT`（默认 30 秒）。更改后须重启后端使
新连接生效；超时是兜底，不能替代只读查询去锁和阻塞操作移出事件循环。

维护者可在本地专用 PostgreSQL 测试库运行并发回归。先在环境中设置
`TEST_POSTGRES_URL`，再执行：

```bash
PYTHONPATH=src/backend pytest src/backend/tests/api/test_site_contention_postgres.py -q
```

测试使用独立临时 schema 和存储目录，结束后清理；覆盖站点面板并发读取、页面访问、
发布等锁期间的健康检查，以及访问计数超时后的页面返回。
