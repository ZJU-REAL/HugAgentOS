# 知识库 Wiki

上传一堆散乱的文档之后，你常常还是不知道「这批资料里到底有什么」。Wiki 就是为这件事准备的：文档入库后，系统用大模型从原文里抽出人物、机构、概念等条目，为每个条目生成一篇**带出处**的 Markdown 页面，页面之间互相链接，形成一个可以像百科一样浏览的知识站点。

它和普通问答的区别在于：问答是「你问我答」，Wiki 是「先替你把知识整理好」。资料越多、越零散，Wiki 的价值越明显。

> **Wiki 是知识库的地图，不是第二个检索源。** 地图负责把范围收窄到正确的位置，
> 答案与出处始终回到原文分块——所以每个页面都能顺血缘按 ID 直取原文，而不是拿
> Wiki 摘要当答案。

自建知识库与具备该能力的外接知识库都提供这层产物，读取接口与前端界面完全一致。

## 怎么开启

1. 新建知识库时，在「索引方式」里勾选 **Wiki 图谱**（与「RAG 检索」同选即 LLM-Wiki 知识库）；
2. 上传文档；
3. 等待生成。Wiki 生成是异步的，文档多时会持续一段时间，知识库详情页的「知识 Wiki」页签会显示进度；
4. 完成后在「知识 Wiki」页签浏览，可切换目录树与概念图谱两种视图。

已经建好的知识库要补开 Wiki：编辑知识库勾上「Wiki 图谱」保存，再点「生成 Wiki」——**改配置不会自动补建**，因为那会实打实消耗模型额度，需要显式确认。

生成过程要调大模型，成本与文档量成正比。抽取密度可在建库时选择（见下文「抽取粒度」）。

## 页面模型

### 页面类型

| 类型 | 说明 |
|---|---|
| `summary` | 单篇源文档的摘要页 |
| `entity` | 实体页（人、组织、产品、地点、技术、事件） |
| `concept` | 概念页（主题、方法论、理论） |
| `index` | 全库索引页 |
| `synthesis` / `comparison` | 综述页 / 对比页，生成管线不产出，预留给智能体写入 |

### 目录树

概念页按目录组织，最深 3 级。目录由模型在生成时**整批规划**——同一批条目一次性分配目录并强制复用已有文件夹，这样同类条目会落在同一个目录下，而不是各自发挥造出一堆同义文件夹。

空目录允许独立存在，收尾阶段会清理既无页面也无子目录的空目录。

### 关键字段

- `slug`：页面在库内的唯一标识，格式 `<类型>/<名称>`，如 `entity/zhongguo-renmin-yinhang`；
- `source_refs`：取材自哪些文档；`chunk_refs`：哪几个原文分块支撑了内容；
- `in_links` / `out_links`：页面之间的双向链接，概念图谱据此构建；
- `aliases`：别名，用于搜索与正文自动织链。

## 生成流程

文档索引完成后自动排入生成队列，由后台 worker 异步执行，分五个阶段：

| 阶段 | 做什么 |
|---|---|
| 候选抽取 | 逐文档抽出实体/概念的骨架：名称、slug、别名、一句话说明 |
| 引文标注 | 逐批分块标注「哪几块实质性讨论了这个条目」 |
| 去重 | 判断新条目是否与既有页面同指一物，是则合并 |
| 目录规划 | 为整批新条目一次性分配目录路径 |
| 撰写页面 | 按条目增量合并/新建页面，随后为每篇源文档写摘要页 |
| 收尾 | 重建索引页、清理死链、重建反向链接、修剪空目录（不调模型） |

有三条贯穿全程的约束，决定了 Wiki 的可信度：

1. **不让模型转述事实。** 引文阶段只回答「哪几个分块讨论了它」，事实以分块原文的逐字形态进入撰写阶段。
2. **撰写时模型是编译器不是作者。** 紧贴原文措辞，不润色、不扩写、不添加「旨在」「致力于」这类修辞填充。新信息若明显属于另一个相关但不同的事物，会被拒绝写入。
3. **相关 ≠ 相同。** 去重只合并同一事物的不同叫法（缩写、译名、全简称），不合并「相关的两件事」——同类目下的不同产品、不同版本、不同证件都不会被合并。

### 抽取粒度

| 粒度 | 行为 |
|---|---|
| `focused` | 仅抽 3-7 个核心主题，索引最干净、成本最低 |
| `standard`（默认） | 主题 + 有独立段落展开的实体概念 |
| `exhaustive` | 见名即收，适合当术语表用；条目多、成本高 |

### 生成模型

在**模型管理**里为角色「知识库 Wiki 实体抽取」（`kb_wiki`）绑定供应商。未绑定时回落主对话模型。

Wiki 是纯离线批处理，调用量随文档量线性增长，**建议单独绑一个便宜模型**。每次生成还有调用次数上限（`wiki_config.max_llm_calls`，默认 4000）作为刹车：达到上限时已生成的部分保留，作业正常结束。

### 失败与恢复

作业状态落库，worker 认领后写心跳。进程重启时，心跳超时的作业会被自动回收重跑——不会出现「重启后半个 Wiki」。作业失败按次数退避重试，耗尽后终止并记录错误。

## 浏览与检索

界面在知识库详情页的「知识 Wiki」页签：左侧目录树按类型分组并逐层懒加载，右侧是页面正文与「原文出处」，另有概念图谱视图展示条目之间的链接关系。

搜索支持交替写法：`资质|牌照|证书` 可以一次给出多个说法——口语说法常常匹配不上书面术语。

### 接口

全部挂在 `/v1/catalog/kb/{kb_id}/wiki` 下，均需要对该知识库的读权限：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/capability` | 该库是否具备 Wiki 能力 + 生成进度 |
| GET | `/stats` | 规模统计 |
| GET | `/pages` | 分页列出页面，支持类型与目录筛选 |
| GET | `/page/{slug}` | 读取单页（含正文、双链、血缘） |
| GET | `/folders` | 目录树的某一层，带递归页面计数 |
| GET | `/index` | 索引总览 |
| GET | `/search?q=` | 检索页面 |
| GET | `/graph` | 概念图谱（overview 全局 / ego 以某点展开） |
| GET | `/source/{slug}` | 顺血缘取回该页对应的原文分块 |
| POST | `/rebuild` | 重新生成（需编辑权限） |

平台级探测用 `GET /v1/catalog/kb/wiki/capability`。

> **权限**：Wiki 是原文的衍生物，可读性与原文完全一致，走与知识库检索同一套判定，
> 不构成绕过知识库授权的旁路。

## 与智能体的关系

启用后，智能体多出五个工具，串成一条**单向链**：

| 工具 | 作用 |
|---|---|
| `wiki_overview` | 看这个库的知识结构长什么样、哪些是主干概念 |
| `wiki_locate` | ① 按词命中概念页/实体页，只回摘要不回正文 |
| `wiki_read_page` | 读取某页完整内容与关系 |
| `wiki_expand` | ② 沿双链把相关概念一次拉齐，适合聚合型问题 |
| `wiki_fetch_source` | ③ 顺血缘按 ID 直取原文分块，答案与出处以此为准 |

工具对自建库与外接库通用，传对应的知识库 ID 即可。

## 生命周期

| 事件 | 行为 |
|---|---|
| 上传文档 | 索引完成后自动排入生成队列 |
| 删除文档 | 自动摘除该文档的血缘；页面失去全部来源则归档 |
| 删除知识库 | Wiki 数据一并删除 |
| 重新索引文档 | 分块 ID 会变化，建议先删除文档再重新上传，或事后点「生成 Wiki」重建 |
