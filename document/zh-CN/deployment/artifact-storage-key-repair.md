# 历史产物存储地址修复

适用于旧版本把 `artifacts/<id>.docx` 等对象登记为 `artifacts/<id>` 的问题。
当前生成流程要求真实存储地址，个人空间文件列表只等待本地改动登记，不再等待所有云端文件下载。
导入窗口把请求失败显示为错误并提供重试，失败不会再显示为“暂无文件”。

## 安全边界

修复只匹配 `storage_key == artifacts/<artifact_id>`。必须确认旧对象不存在、
对应文件名后缀的对象存在、下载字节数与原登记大小一致。服务超时、鉴权失败、
大小不符或找不到替代对象时，保留原记录。真实存在的无后缀对象保持不变。

写入采用带原地址、文件名、大小、更新时间条件的原子更新；不修改内容版本。
原地址、新地址、SHA-256 和原内容版本与新地址一起存入
`metadata.storage_key_repair`，支持审计及有条件回滚。
个人空间投影下载失败时会用同样的校验自动修复；未保存的本地内容仍按原有冲突保护处理。

## 执行

遵守仓库发布授权：预发验证后，生产代码与数据变更必须另行取得用户确认。
在已授权环境的项目根目录执行，使用该环境已有配置与 Python 运行时。
不要复制其他环境的 `.env` 或凭据。

```bash
# 默认只验证、输出候选地址，不改数据库。
PYTHONPATH=src/backend python scripts/repair_artifact_storage_keys.py --user-id <用户ID>

# 确认候选结果后执行；重复运行不会重复修改已修复项。
PYTHONPATH=src/backend python scripts/repair_artifact_storage_keys.py --user-id <用户ID> --apply

# 仅回滚内容版本、当前地址都未变化的已审计修复。
# 回滚会恢复旧地址；若后台投影已升级，仍可能再次进行自动修复。
PYTHONPATH=src/backend python scripts/repair_artifact_storage_keys.py --user-id <用户ID> --rollback
```

工具一次只处理明确指定的账号，按文件 ID 分批读取。错误退出非零，避免把部分失败当作全部成功。
修复既有记录包含回收站中的历史项；不会恢复已删除文件或变更所属目录。

## 验收

1. 地址修复候选、对象大小和审计记录正确；再次运行没有重复改写。
2. 个人空间根目录和原文件目录的列表 API 返回成功；有效文件能下载。
3. Windows 桌面本机模式分别用 `@` 和 `+ → 从我的空间导入` 选择文件，实际发送后可读取正文。
4. 注入单个不存在的对象时，其他文件列表可用；文件获取仍报告真实失败。
5. 请求失败显示错误和重试；切换筛选或目录后旧响应不能覆盖当前结果。

前端源码变化必须随桌面客户端发行才对已安装客户端生效。完成源码构建不代表已经发布，
也不代表现有生产数据已修改；发布记录应注明预发、生产和客户端各自的验证结果。
