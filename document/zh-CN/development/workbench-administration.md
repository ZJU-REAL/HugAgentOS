# 工作台管理员指南

[English](../../en/development/workbench-administration.md) · [预览](workbench-preview.md)

组织配置使用认证后的 Config 应用（商业版 EE）。
创建工作台入口时，不改造既有 SQL/MCP 托管业务应用。
工作台接口使用 /v1/workbench；旧业务接口保留原鉴权。

## 外部网页

创建具有稳定 ID 和中性标题的外部应用声明。
工作区示例提供 external-application.json。

```json
{
  "schemaVersion": "1.0.0",
  "id": "weather",
  "title": "Weather",
  "target": {"kind": "external", "mode": "browser", "url": "https://example.org/weather"}
}
```

提交到 Config 前校验声明。
普通网页在浏览器打开，保留宿主页面。
嵌入需要明确的受信来源配置，并要求目标系统支持。
若 CSP、frame 安全头或 Cookie 阻止嵌入，提供浏览器打开入口。
不得去掉目标系统安全头，也不部署任意网站反代。

## 认证与权限

选择独立登录、共同身份提供方或目标限定换票。
独立登录使用目标系统自己的会话。
共同身份提供方要求双方各自认证，不转交宿主 Cookie 或通用 SSO token。
换票使用短时单次票据，绑定用户、应用、受众和精确回调。
目标服务器兑换时必须认证。
换票秘密和上游数据源凭据只保留在受保护的服务端配置中。
不得把票据或凭据写入公开清单、截图、日志或 URL。
宿主退出撤销宿主资源。目标系统全局退出需要对方明确支持。

目录可见性与实际能力审批分别配置。
固定和隐藏应用属于布局动作。
既有 allowed_apps 保持应用可见策略语义。
启动、数据和文件操作仍须实际鉴权及所有权检查。
策略选择器使用目录返回的准确 applicationKey。
外部 ID 不授予同名插件权限。

## 插件验收

安装前校验并检查插件包。
审查模块请求的能力、数据源目标和升级增加的权限。
从应用中心打开已安装页面。未打开的应用不得创建 iframe 或进程。
用隔离账号及临时文件测试允许和拒绝场景。
在页面打开时停用安装，检查旧通道及访问立即停止。
升级新增权限须审批。
保留原插件包及受保护的数据快照，以便恢复。

参见[错误码](workbench-errors.md)和[迁移](workbench-migration.md)。
