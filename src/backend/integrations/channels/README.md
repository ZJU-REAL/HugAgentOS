# 消息通道

本模块拥有通道连接、设备中继数据、适配器、入站运行、出站投递和附件工具。FULL 与 CE 均安装模型，运行开关不控制建表。API 注册仍由中央有序路由表负责，路由及权限策略保持原样。

入站处理按会话、附件、消息观察、历史拉取及回复投递拆分。inbound_state 是串行锁、去重缓存和限额的唯一所有者。适配器的历史解析、消息解析和发送方法按职责分组；具体适配器保留能力声明及令牌缓存，飞书连接入口保留线程事件循环隔离状态。

依赖 core 的认证、数据库、聊天运行、存储和工具注册接口；桌面中继暂时引用 core 中的桌面服务，P5 随归属迁移。外部调用方直接引用所属模块，不提供旧路径转发。通道账号与个人 OAuth 账号相互独立，入站始终采用机器人所有者身份与原资源范围。

测试位于 tests/integrations/channels。bot_cases 模块按组存放用例，test_channel_bots 显式收集这些函数，以保留原测试节点身份及失败基线映射；不减少用例或断言。
