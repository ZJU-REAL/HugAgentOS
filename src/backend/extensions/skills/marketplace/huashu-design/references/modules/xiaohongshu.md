# 模块 · 小红书图文 / 封面 / 轮播

一组近似 3:4 的竖图在小红书里左右滑着读，也包括只做一张封面（头图）。第一张在双列信息流里和别人的封面挤在一起，决定点不点开；后面每张是一页。先过 SKILL.md 的窄桥，再按这份手册做。单张以数据为主角的竖长图走 `infographic.md`。

## 规格

- 画布 1242×1660（小红书常用的近似 3:4；精确 3:4 是 1080×1440，也可以用，字号按比例换算）。一篇最多 18 张。
- 字号底线（1242 宽画布）：正文 ≥42px、标签 ≥32px，等于 1080 宽的 36/28。封面标题在信息流里只有约三分之一屏宽，要 ≥100px，两行内说完。
- 平台限制写进设计：图里不放外链、二维码、微信号、邮箱，要引导就写「GitHub 搜 xxx」「评论区说一声」；不写「最好」「行业第一」「唯一」这类绝对化宣称（「第一步」「第一个网页」这种序数不算；用户原话里的「最值的一笔」改成「值回票价的一笔」这类具体说法）；用了 AI 生成的画面，发布时按平台要求做内容声明；用了 CC BY 类图片，在图上或正文末写作者和许可。

## 先选范式（三方向门在这里的样子）

三方向 = 三个范式，各出「封面＋一张最难的内页」，用 `xhs_render.py` 的 sheet.jpg 并排给用户；只做一张封面时，每个方向出一张封面。六个候选照 `directions.md` 构思，秒数轮盘在这 8 个范式里抽；最后挑出的三版要落在三个不同范式上。范式池是 `design-styles.md`「小红书图文（8种）」，总览 `assets/style-specimens/sheet-xhs.jpg`。

| 内容 | 先想到 |
|---|---|
| 自家产品、想让人一眼认出是你的东西 | 02 贴纸本（借产品界面的纸、控件、素材） |
| 能排成一条线：一组对象、时间线、流水线 | 04 长卷（几张连成一幅） |
| 自然、知识、文化长文，要权威和杂志感 | 01 标本志 |
| 数字结论、排行、清单 | 03 索引、08 信息图 |
| 发布、复盘、方法稿这类「事件」 | 05 日报 |
| 一项一卡、可收集：物种、产品、人物、工具 | 06 集换卡 |
| 慢内容、故事、单个对象的特写 | 07 留白 |

范式只给骨架。颜色按色彩推导协议从内容或品牌里取，素材用用户自己的真东西（`references/materials.md`），三个方向的骨架要不同。

## 从模板起步

八个样张同时是模板：把 `$HD/assets/style-specimens/xhs/<编号>.html` 和 `_kit/xhs.css`、`_kit/xhs.js` 复制进项目（放在项目的 `_kit/` 下，路径就不用改），改字、换图、改 `:root` 的颜色。浏览器窗口 1200×750 打开是并排样张，其他宽度按真实尺寸排。

- 一页一个 `<section class="xhs-page">`；连续长卷用 `<section class="xhs-strip" style="--n:3">`，宽 1242×N。
- `_kit/xhs.js`：`XHS.number(总张数)` 写页码（封面加 `data-pageno="off"`）；`XHS.wire()` 画一条跨图连续的线，`XHS.perch()` 让对象站在线上，`XHS.straddle()` 把对象跨在第几道缝上。
- `_kit/stickers/` 和 `birds.js` 是演示用的鸟类贴纸，许可是 PolyForm Shield，和本仓库的 MIT 不同：模板里引用它们的地方直接换成用户的图和数据，不要把它们带进项目。
- 模板用 Google Fonts 外链，字体栈里有系统字体兜底；离线时删掉 `<link>` 也能排，只是字形会变，出图前看一眼。

## 一组图怎么排

- 封面：一个钩子（数字、结论或反差）＋一个主视觉，八到十四个字的标题。不要把目录塞进封面。
- 第二张交代「这是什么」；中间一张讲一件事，一句标题配一个画面；最后一张落在下一步（去哪找、怎么用、评论区说什么）。
- 整组一个系统：同一套页眉、页码、颜色和字体；相邻两张换构图（大图、清单、数字、对比轮着来）。
- 长卷：主角跨缝（左图露约 2/3，右图露约 1/3），往右滑才接上；每张单看也要有标题、讲得通；连续的线、地平线用同一个函数画，别每张各画一段。

## 出图与体检

```bash
# $HD = 本 skill 的根目录（SKILL.md 所在目录），不是用户的项目目录
python3 "$HD/scripts/xhs_render.py" 笔记.html --out 配图/ --jpg
```

脚本逐页出 `01.png`…，长卷自动切张，再拼一张 `sheet.jpg`。它会查：字号低于底线、字出了页面、长卷里字跨缝、两段字压在一起（这四样是 ✗，退出码为 1）；字被图片或色块盖住、字和小色块挤在一起是 !：要么改掉，要么在交付说明里写为什么保留。有意叠放的元素加 `data-overlap-ok`。通用体检照常可跑，竖版要给全视口：`design_lint.py check … --viewport 1242x1660 --min-body 42 --min-label 32`（`compare`、`ledger check` 同样带 `--viewport 1242x1660`），署名、图注这类长标签的类名里带 `caption` 或 `credit`，体检才按标签算。没有 ✗ 不等于能交付，脚本查不出版式塌掉（网格挤成一列、图表没画出来），要逐张打开原尺寸 png 看，再看 sheet.jpg：标题末行孤字、页底组件撞页码、只有一行的正文按标签底线放过了、整组节奏是不是每张都一样。

## 踩过的坑

- Bodoni 这类高反差衬线小于 100px 时，细笔画在手机上会断，「4」看成「1」。小数字换成宋体或无衬线。封面在信息流里还要再缩到约三分之一，封面上的高反差数字按 ≥200px 算。
- 页面底部的卡片、数字条最容易撞上页码和页脚，最后一张尤其要看。
- 样张模式整体缩放过，脚本里量宽度用 `offsetWidth`，不要用 `getBoundingClientRect()`，否则长卷的线只画了三分之一。
- 页面脚本别用 `top`、`name` 当变量名，会撞浏览器全局，整块空白也不报错。
- 小格子放不下 32px 的字，就合并成「其余 N 个」或只放图，不要为了塞进去把字缩小。
