# 例会待办跟踪

例会真正的价值在于上次说的事这次有没有落实。本技能为每个系列例会维护一份待办台账，
模型负责从纪要中提取待办和进展，脚本负责编号、状态流转、去重、逾期判断和导出。

下文 `scripts/` 指本技能目录 `{baseDir}/scripts/`。

## 台账放在哪里

- 每个系列例会一份 JSON 台账，例如 `例会台账/产品部周例会.json`，保存在用户的个人空间或项目文件里，
  这样下次会议还能接着用。**第一次建立时告诉用户台账的位置**。
- 下次使用时先找到这份台账；找不到就问用户，不要新建一份重复的台账。

状态只有五种：`未开始`、`进行中`、`已完成`、`延期`、`取消`。`已完成` 和 `取消` 视为关闭。

## 流程 A：会前，准备回顾清单

```bash
python3 scripts/tracker.py open --ledger 例会台账/产品部周例会.json
python3 scripts/tracker.py export --ledger 例会台账/产品部周例会.json -o 待办台账.xlsx
```

`export` 同时生成 `待办台账.md` 回顾清单：按负责人分组，逾期的排在最前，附上次进展。
把回顾清单发给用户，或作为会议议程的第一项。

## 流程 B：会后，登记本次会议

1. **获取会议内容**：如果安装了腾讯会议工具，用它查询本次会议的智能纪要或转写全文；否则请用户粘贴纪要或转写文字。
2. **第一次使用**时先建台账：
   ```bash
   python3 scripts/tracker.py init --ledger 例会台账/产品部周例会.json --series 产品部周例会
   ```
3. **登记会议和新增待办**。从纪要中提取明确的行动项（有动作、有对象），写成 JSON：
   ```bash
   python3 scripts/tracker.py add-meeting --ledger 例会台账/产品部周例会.json \
       --date 2026-11-03 --title 第45周例会 \
       --items '[{"title":"输出竞品分析报告","owner":"李四","due":"2026-11-10"}]'
   ```
   - 只记纪要里明确说了的负责人和日期。没说的就不填，脚本会提示"没有负责人或截止日期"，**把这些提示转告用户确认**，不要自己指定。
   - "下周五""月底"这类说法换算成具体日期（YYYY-MM-DD），换算依据是会议日期。
   - 和未关闭事项重复的待办会被自动跳过。
4. **登记旧待办的进展**，用上一步返回的会议编号：
   ```bash
   python3 scripts/tracker.py update --ledger 例会台账/产品部周例会.json --meeting M002 \
       --updates '[{"id":"A001","status":"已完成","note":"已评审通过"},
                   {"id":"A002","status":"延期","due":"2026-11-17","note":"数据未到"}]'
   ```
   - 纪要里没提到的旧待办不要改状态，在回复里列出来，提醒用户会上没有过这几项。
   - 标为 `延期` 时要带新的截止日期。
5. **导出**最新台账，向用户汇报：本次新增几项、关闭几项、仍逾期的事项和负责人。

## 可选：定时提醒

用户需要时，可以用自动化任务功能设置提醒，比如每周一上午生成回顾清单发给用户。
**创建前把执行时间和内容告诉用户，确认后再创建**。
