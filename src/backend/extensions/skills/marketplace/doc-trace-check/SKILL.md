# 公文依据溯源

公文和汇报材料最怕两件事：数字、文号、政策名称写错；没有依据的内容被当成事实写进去。
本技能把"写"和"核"分开：先检索建立依据台账，写作时逐处标注出处，写完由脚本逐句核验。

下文 `scripts/` 指本技能目录 `{baseDir}/scripts/`。文种格式（GB/T 9704 版式、红头、版记）交给
`govwriter-pro`、`doc-format-gw` 或 `officecli-docx` 处理，本技能只管内容依据。

## 第 1 步：明确任务

问清（用户已说明的不再问）：文种、主送对象、核心事项、需要引用的政策或数据范围、时间口径（如"2025 年全年"）。

## 第 2 步：检索依据，建立台账

- 先用 `retrieve_dataset_content`（公有知识库）检索政策原文、统计公报、工作总结等；用户自己上传的材料用 `retrieve_local_kb`。
- 知识库查不到时，可以用 `internet_search` / `web_fetch`，**只采信政府网站（gov.cn 及各级政府、部委官网）和统计部门发布的原文**，不采信自媒体和转载。
- 每条要用的依据写进 `依据台账.json`，`quote` 必须是原文摘录，不要概括：

```json
[
  {"cite_id": "e1", "title": "关于推动制造业数字化转型的实施意见", "issuer": "工业和信息化部",
   "doc_no": "工信部发〔2024〕12号", "date": "2024年5月", "url": "https://...",
   "quote": "到2027年，规上工业企业数字化改造覆盖率达到80%以上。"}
]
```

`cite_id` 直接沿用检索结果自带的 `cite_id`；网页来源自己按 `w1`、`w2` 编号。

## 第 3 步：带标注写草稿

- 每个数字、金额、比例、文号、日期、《文件名》后面都用平台引用标记标出处：`增长[6.8%](cite:e2)`。
- 依据里没有的数字、文号、人名、日期，**一律写 `[待补]`，绝不编造**，也不要用"约""左右"掩盖。
- 观点、部署、表态类句子不需要引用。
- 草稿存为 `草稿.md`。

## 第 4 步：逐句核验

```bash
python3 scripts/trace_check.py --draft 草稿.md --ledger 依据台账.json \
    -o 溯源核验报告.docx --render 定稿.md
```

每句会得到一个状态：

| 状态 | 含义 | 怎么处理 |
|---|---|---|
| 已溯源 | 有引用，且句中数字和文号都能在所引原文里找到 | 无需处理 |
| 与依据不符 | 有引用，但数字或文号在所引原文里找不到 | 回到台账核对，以原文为准改正文 |
| 缺少依据 | 有硬信息但没有引用 | 补检索并加引用；查不到就改成 `[待补]` |
| 引用无效 | cite_id 不在台账里 | 补台账，或删除该引用 |
| 待补 | 含 `[待补]` | 交付时提醒用户补齐 |

脚本返回码为 1 表示还有前三类问题。**修改后重新运行，直到没有前三类问题再交付**。
如果确实无法解决（比如原文本身表述不同），在交付说明里逐条告诉用户，不要自行删除核验结果。

## 第 5 步：交付

- `定稿.md`：引用标记已换成上标序号，文末附依据清单；再交给公文排版技能生成 Word。如果正式公文不需要角标，排版时去掉上标和清单即可，依据清单单独附给审核人。
- `溯源核验报告.docx`：逐句列出依据和原文摘录，供审核人复核。
- 在回复中列出所有 `[待补]` 项，请用户补齐。
