# 发票识别与报销审核

脚本做确定性的工作：抽字段、按规则比对、汇总；模型负责补齐脚本没抽到的字段、和用户确认报销规则、解释问题。

下文 `scripts/` 指本技能目录 `{baseDir}/scripts/`。

## 第 1 步：确认报销规则

第一次使用时问清以下内容，写成 `policy.json`，以后复用（用户没有规则的项就不填，对应检查会跳过）：

```json
{
  "company_name": "某某科技有限公司",
  "tax_id": "91110108MA01ABCD2X",
  "max_age_days": 90,
  "category_limits": {"餐饮": 1000, "住宿": 3000},
  "category_keywords": {"餐饮": ["餐饮"], "住宿": ["住宿"], "交通": ["运输", "客运", "交通"],
                        "办公": ["办公", "文具", "纸制品"]}
}
```

- `company_name` / `tax_id`：发票抬头必须一致。
- `max_age_days`：开票后多少天内可报。
- `category_limits`：本批次各类别的累计限额（元）。
- `category_keywords`：发票上税收分类（如 `*餐饮服务*餐费` 里的"餐饮服务"）包含哪些词就归到哪个报销类别。

## 第 2 步：抽取发票字段

```bash
python3 scripts/invoice_extract.py <发票目录或文件...> -o invoices.json
```

- 带文字层的 PDF 电子发票可以直接处理。
- **图片、拍照件、扫描件**：先用 OCR 工具（如已安装的百度 OCR）识别成文字，存成同名 `.txt` 再一起传入。
- 输出中 `missing` 列出没抽到的字段。**对照该条记录的 `text` 原文补齐或更正 `invoices.json`**；原文里确实没有的就留空，不要猜。

## 第 3 步：规则检查与汇总

```bash
python3 scripts/reimburse_check.py --invoices invoices.json --policy policy.json \
    --history 已报销发票号.txt -o 报销汇总.xlsx
```

- `--history` 可选：历史已报销的发票号码，每行一个，用来发现跨批次的重复报销。审核通过后，把本批发票号码追加进这个文件（先征得用户同意）。
- 输出 `报销汇总.xlsx`，包含三个工作表：
  - **报销明细**：每张发票的结论和问题；
  - **分类汇总**：各类别张数、金额、可报销金额；
  - **查验清单**：真伪查验所需的发票代码、号码、日期、不含税金额、校验码后 6 位。

## 第 4 步：交付

向用户说明：
1. 可报销张数和金额；
2. 每张"需处理"发票的问题和建议（比如抬头不符需要重开，重复的需要剔除）；
3. **真伪查验**：国家税务总局全国增值税发票查验平台（https://inv-veri.chinatax.gov.cn）需要输入验证码，必须由用户本人操作。请用户按"查验清单"逐张查验。不要尝试自动查验或绕过验证码。

是否符合报销制度的最终判断由财务人员做出，本技能的结论仅供初审参考。
